# 21열 × 13행 스윗 스팟 수집 · 2026-11-23

앱 1.13.0(15)의 첫 탭 **273점 수집**을 사용합니다. 기존 수집 앱을 확장한 절차이며, 새로운 연구 구현 폴더를 만들거나 기존 모델을 교체하지 않습니다.

## 준비

- [A4 가로 도면](../../output/pdf/sweet_spot_50x30mm_pitch2p5mm_a4_landscape.pdf)을 실제 크기 100%로 인쇄하고, 가능하면 가로 50 mm·세로 30 mm를 실측합니다. 페이지 맞춤과 자동 축소를 끕니다.
- 종이·iPad·스탠드·케이블·주변 물체를 고정합니다. iPad의 각도·높이, 충전·케이스 상태, 플라스틱 홀더 설명을 **배치 확인** 화면에 기록합니다.
- 이번 수집은 **φ=0°, θ=90°, 펜촉 높이 0 mm·표면 접촉**입니다. 펜 끝을 종이에 가볍게 대고, 기존 데모 방향(로고 왼쪽)을 유지합니다. 이번 39묶음에 다른 각도·높이를 섞지 않습니다.
- 위쪽(iPad 쪽)이 **1행**, 아래쪽(사용자 쪽)이 **13행**입니다. 왼쪽부터 **1–21열**, 중앙은 **7행 11열**입니다. 모든 방향은 사용자가 도면을 바라보는 기준입니다.
- 배경 측정 때는 펜슬과 함께 움직이는 홀더를 같은 먼 위치에 놓습니다. 실시간 Bx·By·Bz가 펜을 더 멀리 옮겨도 거의 달라지지 않는 위치를 사용합니다. iPad와 종이를 옮기지는 않습니다.

## 반복과 순서

**273점 × 3회 = 819번의 독립적인 정지 측정**을 모두 학습 자료로 모읍니다. 같은 점에 놓인 상태로 세 번 재는 대신, 다른 회차에 다시 놓습니다. 세 번은 위치를 다시 맞출 때의 변동을 확인할 최소한의 반복으로 선택했으며, 신호가 불안정한 곳은 분석 후 추가 수집할 수 있습니다. 2.5 mm 점 간격 자체가 2.5 mm 추정 정확도를 보장하지는 않습니다.

| 회차 | 행 순서 | 행 안의 순서 |
|---|---|---|
| 1 | 1 → 13행 | 1행 왼쪽→오른쪽, 다음 행 반대인 지그재그 |
| 2 | 13 → 1행 | 각 행의 1회차 방향을 반대로 |
| 3 | 7, 1, 13, 4, 10, 2, 12, 5, 9, 3, 11, 6, 8행 | 각 행에서 인접 열 순서로 진행; 앱의 화살표를 따름 |

시간에 따른 배경 변화와 위치 순서가 항상 겹치지 않도록 순서를 바꿉니다. 3회차도 학습용이며 별도 검증이 아닙니다. 각 행을 따로 저장하지만 **39개 행 묶음을 모두 모아 한 데이터셋으로 학습**합니다. 행 하나씩 학습·테스트를 반복하지 않습니다.

## 각도·높이 조건과 iPad 경사

배치 확인 화면에서 장치의 조건을 숫자로 입력합니다. 시작한 배치에서는 조건을 고정하며, 나중에 값을 바꾸려면 **새 배치로 시작**으로 다른 `campaignID`를 부여합니다.

| 항목 | 정의 / 출처 |
|---|---|
| φ (phi) | 홀더 전체를 **책상 수직축** 주위로 회전. 위에서 보아 시계방향이 양수. 기존 데모 홀더 방향=0°. 입력 0–360°, 360°는 0°로 저장. 사용자가 장치에서 맞춘 값 |
| θ (theta) | 펜 축과 지면 사이의 각도. 수평=0°, 수직=90°. 사용자가 장치에서 맞춘 값 |
| 펜촉 높이 | 책상/종이 표면에서 펜 끝까지의 **연직 거리 mm**. 접촉이면 0, 공중이면 양수. 장치 설정값 |
| 접촉 여부 | 사용자가 지정한 접촉/공중 라벨. 센서로 접촉을 검출한 결과가 아님 |
| iPad 화면 경사 | Core Motion 중력 벡터에서 계산한 **화면 평면과 중력 기준 수평면 사이의 각도**. 눕힘=0°, 직립=90°. 기기 높이는 이 값으로 알 수 없음 |

φ는 Pencil 자체의 긴 축을 중심으로 도는 회전(roll)과 다릅니다. θ=90°에서는 펜 축의 수평 투영 방향이 사라지지만, φ는 홀더의 기준 방향으로 계속 정의합니다. 기울인 수집에서는 **φ=0에서 θ를 낮출 때 기울어지는 방향**도 기록해야 합니다. 펜을 그립 안에서 따로 돌리지 않고, 고정 방향·기준점을 메모로 남깁니다. 공중 수집의 격자점은 펜촉의 수직 투영 위치입니다.

iPad 경사는 `acos(abs(gz)/sqrt(gx²+gy²+gz²))`를 도 단위로 바꿉니다. 가로·세로 화면 전환에 영향을 받지 않는 0–90°의 경사 크기이며 기울임 방향 자체는 원시 중력 벡터와 quaternion에 남습니다. 책상이 수평일 때만 책상 기준 경사와 같고, 움직이는 중에는 오차가 커질 수 있습니다. `manifest.ipadInclinationAtStart`에 행 시작 시 최근 값을, `device_motion.csv`의 `ipad_screen_inclination_deg`에 각 샘플 값을 기록합니다. 센서가 없거나 값이 오래됐으면 화면에 수신 대기로 표시합니다. 원시 중력값 제공 방식은 [Apple CMDeviceMotion 문서](https://developer.apple.com/documentation/coremotion/cmdevicemotion)를 따릅니다.

## 한 행의 실제 진행

1. **시작 배경**: 펜과 이동 홀더를 멀리 놓고 시작. 준비 3초 + 배경 10초.
2. **21점**: 화면의 행·열 번호와 주황색 점을 보고 해당 검은 표식에 펜 끝을 놓습니다. 직접 시작 버튼을 누르고 준비 3초 + 정지 3초. 완료 안내 후 다음 점으로 이동합니다. 이동 시간은 자유입니다.
3. **종료 배경**: 펜과 홀더를 시작 배경 때의 먼 위치로 옮깁니다. 준비 3초 + 배경 10초. 완료 후 행이 자동 저장됩니다.
4. **휴식 / 다음 행**: 저장 완료를 확인하고 쉽니다. 다음 미완료 행 버튼으로 이어갑니다. 화면 상단 진행률은 실제 저장 파일을 확인해 표시합니다.

한 행은 23항목(21점+배경2개), 전체는 **39묶음·897항목**입니다. 순수 준비·측정 시간은 98.8분, 센서 지연 수신 대기까지 약 105분입니다. 이동·버튼 조작·휴식을 포함하면 **약 2–3시간**, 행당 약 3–5분을 예상합니다. 한 번에 오래 버티기보다 저장된 행 사이에서 쉬세요.

측정 버튼은 화면 아래에 고정됩니다. 잘못 놓았거나 흔들렸다면 측정 중 **취소·다시 측정**, 다음 항목으로 넘어간 직후에는 **직전 다시**를 사용합니다. 기존 시도는 원본에 남지만 `aborted` 또는 `invalidated`로 제외합니다. 종료 배경 이후에 오류를 알아챘다면 해당 행 전체를 다시 측정합니다.

잠금·앱 종료·중간 종료 시 진행하던 행은 미완료입니다. 그 행만 시작 배경부터 다시 재며, 완료된 행은 유지됩니다. 전체 배치가 달라졌다면 **수집 관리 → 새 배치로 시작**을 사용합니다. 새 수집 번호를 부여하고 기존 파일은 삭제하지 않습니다. 시작한 배치의 조건 기록은 고정됩니다.

## 저장과 이후 학습

`Documents/MagAirSessions` 아래에 행마다 세션 하나를 저장합니다. 맥북에 연결하면 전체 자료를 직접 가져올 수 있으므로 ZIP 39개를 수동으로 옮길 필요는 없습니다. 파일 앱이나 저장 기록의 ZIP 공유도 계속 사용할 수 있습니다.

`manifest.printedGrid`에 프로토콜 `sweetspot_21x13_v1`, 공통 `campaignID`, 회차·행, 용지·영역 치수와 오프셋을 기록합니다. `gridColumns=21`, `gridRows=13`이며 정사각형 격자용 `gridSize`는 쓰지 않습니다. 정지점은 `printed_grid_train`, 배경은 `printed_grid_baseline`입니다.

| 좌표 | 정의 |
|---|---|
| CSV `target_x`, `target_y` | `x=(열-1)/20`, `y=(행-1)/12`; 영역 왼쪽 위 원점 |
| trial `nominalPointMM` | `(2.5×(열-1), 2.5×(행-1))`; 왼쪽 위에서 오른쪽·아래로 mm |
| 용지 왼쪽 아래 기준 mm | `(115+50×x, 85-30×y)` |

이 값은 사람이 확인한 인쇄 표식의 목표 좌표이며 실제 펜 끝을 계측한 좌표가 아닙니다. `printedGrid.pose` 및 각 정지점의 `trial.spec.fixturePose`에 장치의 φ·θ·높이·접촉·기준 설명을 저장합니다. CSV의 `fixture_phi_deg`, `fixture_theta_deg`, `fixture_tip_state`, `fixture_pose_source`, `instructed_tip_height_mm`는 정지 측정 구간에만 라벨을 붙이며, 펜을 멀리 치운 배경·이동·준비 구간에는 붙이지 않습니다. 각도·높이·접촉의 출처는 `operator_set_fixture_unmeasured`이며 자동 실측값으로 해석하지 않습니다.

자력계는 원시 3축 µT, IMU는 **iPad**의 가속도·자이로·자세입니다. Pencil 원시 IMU나 홀더 좌표를 추론 입력으로 사용하지 않습니다. 미래에 여러 φ·θ·높이·iPad 경사의 자료를 모아 일반화하는 모델을 만들지는 아직 구현·검증하지 않았습니다. 현재 앱은 조건별 수집과 라벨 보존을 지원합니다.

완료 판정은 23항목의 순서·역할·좌표·측정 종료 시각·중복 여부와 종료 배경을 확인합니다. 이 판정은 수집 완료 여부이며 센서 신호 품질 합격을 뜻하지 않습니다. 같은 행의 재수집 파일은 모두 보존하며, UI는 가장 최근의 완전한 묶음을 완료 이력으로 사용합니다. 분석 시에는 배치마다 사용할 세션 하나를 명시적으로 고릅니다.

수집 후에는 같은 `campaignID`의 39묶음을 확인하고, 각 행의 앞뒤 배경·iPad 움직임·센서 공백·정지 구간 산포·반복 간 편차를 분석합니다. 세 회차를 모두 사용해 모델을 만든 뒤 **자유 실시간 테스트 → 별도 수집한 검증** 순서로 진행합니다. 반복 프레임을 무작위로 나눠 독립 검증으로 보고하지 않습니다. 기존 `build_dense_grid_model.py`는 9×9 전용이므로 새 형식을 입력하지 않습니다. 21×13 모델 생성 및 실제 정확도 검증은 새 자료 수집 이후의 작업입니다.

현재 번들 모델과 과거 5×5·9×9 원본은 유지됩니다. 이전 배치의 모델을 새 도면에 대해 검증된 모델로 해석하면 안 됩니다.
