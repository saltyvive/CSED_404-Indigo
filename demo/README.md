## 9×9 모델 생성과 한계

`scripts/build_dense_grid_model.py`는 **정확히 9개 완료 세션**(각 묶음당 하나)을 명시적으로 입력받습니다. 구형 5×5나 검증·왕복 자료를 자동으로 섞지 않습니다. 새 9×9만으로 현재 배치의 지도를 만들고, 동일한 위치의 반복 측정값을 합칩니다.

- 각 정지 측정의 앞 0.4초/뒤 0.2초를 제거한 뒤 3축 중앙값을 사용합니다. 행별 전후 배경으로 오프라인 선형 배경 보정을 합니다. 센서 수신량·공백과 수동 좌표 라벨을 검사합니다.
- 움직임 경고가 있는 행, 불안정한 배경/정지 측정은 경고와 원본을 남기고 기본적으로 제외합니다. 같은 위치에 서로 다른 회차의 정상 측정이 최소 2개 있어야 모델을 생성합니다. 부족하면 분석 파일에 재검토 위치를 기록하고 모델 생성을 멈춥니다. 실제 경고는 수집 후 원시 IMU와 함께 검토합니다.
- 각 위치의 정상 반복 측정을 **회당 같은 가중치로 3축 중앙값** 집계합니다. 프레임 수가 많다고 그 회차를 더 크게 반영하지 않습니다. 반복 간 최대 자기장 거리·산포를 별도로 보고합니다. 마지막 지도는 사용 가능한 세 회차 전체로 만듭니다.
- 9×9 격자의 쌍선형 보간은 유지합니다. 위치 후보는 **161×161**로 하여 1/8 간격 표식이 정확히 후보에 포함됩니다. 후보 간격 0.625%는 측정 정확도 보장이 아닙니다. 반복 변동이 크다고 표시 허용치를 무작정 넓히지 않습니다.
- 한 회차 전체를 빼고 나머지로 맞혀 보는 내부 진단도 기록합니다. 테스트 입력은 각 행의 시작 배경만 사용합니다. 이는 알려진 표식에서의 수집 일관성 진단이며 새로운 위치·이동·글씨 또는 최종 모델의 독립 검증이 아닙니다. 세 회차는 최종 모델에는 모두 사용합니다.
- 완성 후 실제 새 지도를 앱에 넣어 자유 테스트합니다. 9×9 지도용 행·열 안내와 그림은 준비돼 있으며 안내선을 추정 입력에 사용하지 않습니다. 이후 새 세션으로 독립 검증합니다. 펜 자세를 측정하는 기능은 없으므로 밀도가 늘었다고 자세 오차가 해결되는 것은 아닙니다.

```sh
# SESSION_16A ... SESSION_18C는 실제 완료 세션 디렉터리 9개로 교체합니다.
python3 scripts/build_dense_grid_model.py SESSION_16A SESSION_16B SESSION_16C \
  SESSION_17A SESSION_17B SESSION_17C SESSION_18A SESSION_18B SESSION_18C \
  --out reports/grid9-new-run
```

이번 원본은 `data/edge-top-20261015`, 보고서는 `reports/edge-top-20261015/quality_summary.json`입니다. 15항목과 자력계 13,761개가 저장됐습니다. 정지 중 중앙 잡음은 약 0.67µT지만, 시작·종료 배경은 약 20.91µT 달랐습니다. 반복 회차를 서로 바꿔 예측한 기준점 오차는 폭 대비 중앙값 0.625%, 최대 2.75%로, **같은 세션·같은 수동 기준점 반복 검사일 뿐 독립 좌표 정확도가 아닙니다**. 이동 데이터 중 잔차 기준을 통과한 비율은 40–43%로, 이것도 위치 정확도가 아닙니다. 이동 중 배경 변화와 자세·기준점 사이 곡선 오차를 아직 분리하지 못했습니다.

실시간 배경은 약 1분마다 펜을 치우고 새로 맞춰 보세요. 자동 드리프트 보정은 하지 않습니다. 테스트 결과는 앱 `Documents/MagAirEdgeLiveTests`에 CSV·모델 사본·배경 측정 원본을 자동 저장합니다. 이 파일은 **예측 결과**이며 수집 세션의 정답 좌표와 구분합니다. `accepted`, `candidate_shown`, `ambiguous`를 각각 저장하며 신호 약함·잔차·여러 후보 위치의 모호함을 검사합니다. iPad 이동이나 센서 중단 시 새 배경이 필요합니다.

## 첫 단계 기록 · 한 변씩 수집 1.5

먼저 **01 위쪽 변 학습**만 완료하고 분석을 기다립니다. 위쪽은 iPad 쪽입니다. 위쪽 변의 양 끝·가운데·그 사이 두 점, 총 5곳만 표시합니다. 종이띠를 변 길이에 맞춰 두 번 접어 대략 4등분할 수 있습니다. 내부 격자나 자는 필요 없습니다.

1. `한 변씩 수집` → `실험 조건 확인하고 준비 완료`에서 조건을 확인합니다.
2. 배경 → 5개 기준점 × 2회 → 편한 속도의 왕복 3회 → 마지막 배경, 총 **15항목**입니다. 각 항목은 직접 시작합니다.
3. 기준점은 준비 3초 + 정지 3초입니다. 이동 시간은 자유이며 자동으로 다음 위치를 측정하지 않습니다.
4. 왕복은 왼쪽에서 시작해 오른쪽 끝을 거쳐 왼쪽으로 돌아옵니다. 양 끝에서 잠시 멈추고, 돌아오면 **왕복 완료·저장**을 누릅니다. 움직이는 안내점은 없으며 3분을 넘으면 미완료 처리합니다.
5. 마지막 배경 측정 후 **자동 저장·종료**합니다. 수집 완료라고 알려주거나 `저장 기록`에서 ZIP을 공유합니다. 실수한 항목은 취소 후 다시 측정할 수 있고, 다음 항목을 시작하기 전 직전 항목도 재측정할 수 있습니다.

준비된 후속 묶음: 위쪽 검증 / 아래쪽 학습·검증 / 위·아래 구분 / 왼쪽 학습·검증 / 오른쪽 학습·검증 / 네 변 구분 / 위쪽 변 양 끝·가운데의 기울기·축 회전 영향. 새 모델 반영 후 단계별로 안내하며 한 번에 모두 수집하지 않습니다.

각 검증 묶음은 학습과 별도 세션입니다. 순서를 바꾼 5개 정지점과 보통·느림·중간 정지 왕복을 수집합니다. 여러 변 구분에서는 변을 번갈아 측정하여 시간 드리프트 영향을 점검합니다. 자세 검사는 준비 후 수직 정지 3초, 자세 변경 4초, 원래 자세 3초이며 펜 끝은 고정합니다. 실제 각도·접촉은 측정하지 않습니다.

새 분석 명령:

```sh
python3 scripts/build_edge_model.py /path/to/top-train /path/to/top-test --out reports/edges
```

완료된 같은 배치의 세션만 입력합니다. `edge_model.json`은 변별 PCHIP 자기장 곡선이며 `edge_report.json`은 별도 정지점 검증·배경 변화·왕복 진단·자세 변화 보고입니다. 입력 중 각 변의 가장 최근 학습 세션을 사용하고, 같은 세션의 각 기준점에 2회 학습이 있어야 합니다. `edge_test`는 어떤 경우에도 학습하지 않습니다. `known_edge_only` 왕복의 x/y는 비어 있으며 시간으로 정답 위치를 만들지 않습니다. 공유 모서리는 변 분류 평가에서 제외합니다. 끝 배경이 빠지거나, 배경이 불안정하거나, 배경 이후 iPad 움직임 경고가 있으면 자동 학습을 멈추고 원본을 검토합니다.

모델의 정지점 검증은 반복성 검사입니다. 보지 않은 내부 위치·움직이는 실제 좌표 정확도와 다릅니다. 1.6에 위쪽 곡선 실시간 테스트를 추가했습니다. 좌표 시간 추적 필터는 아직 적용하지 않았습니다. `이전 모델 테스트` 탭은 1.4의 네 모서리 모델입니다.

## 실시간 테스트 · 1.4

1. **수집 당시의 iPad·스탠드·사각형·케이블·주변 물체 배치**를 유지합니다. 펜은 책상과 수직, 로고는 왼쪽입니다.
2. 앱의 **이전 모델 테스트** 탭에서 펜을 충분히 멀리 두고 **배경 맞추기 (5초)**를 누릅니다. 처음 2초는 준비, 뒤 3초는 배경 측정입니다.
3. 먼저 **책상 접촉** 모드에서 네 모서리를 차례로 짚어 점이 어디에 표시되는지 확인하고, 천천히 테두리와 대각선을 움직여 보세요. 화면에 따라야 할 이동 안내점은 없습니다. 움직임은 자유롭게 합니다.
4. **약 1cm 공중** 모드는 별도 모서리 모델을 사용합니다. 높이를 자동 판별하지 않으므로 직접 모드를 선택합니다. 높이·기울기 오차는 XY 오차와 섞일 수 있습니다.
5. **궤적 지우기**로 화면을 비우고, **테스트 기록 저장**으로 추정 좌표·자기장·배경·판정 결과를 CSV에 저장합니다. 한 번에 최대 30분(18,000회)이며 파일 앱의 `MagAirLiveTests`에서 CSV와 모델 사본을 확인할 수 있습니다. 이 CSV의 좌표는 정답이 아닌 예측값입니다.

모델은 각 모서리의 3축 자기장 중앙값 사이를 bilinear 방식으로 보간한 뒤 현재 신호에 가까운 좌표를 찾습니다. 위치와 자기장의 관계가 내부에서도 그 모양이라는 **미검증 가정**입니다. 경로 안내 시간은 학습에 사용하지 않았습니다. 배경 자기장은 시작/종료 측정 사이에서 선형 보정했고, 종료 배경 이후의 공중 실험에는 마지막 배경값을 사용했습니다. 그 이후의 드리프트는 직접 관측되지 않았습니다.

신호가 약하거나 모델에서 벗어나거나 영역 밖으로 추정되면 점을 숨기고 궤적을 끊습니다. 표시 중에도 정확도를 보장하지 않습니다. 화면의 µT 잔차는 위치 오차·신뢰도 %가 아닙니다. 약 0.12초 중앙값 필터와 약 10Hz 표시를 사용합니다. iPad가 흔들리거나 앱이 배경으로 가면 배경 보정을 다시 요구합니다. 배치가 달라진 경우 배경 보정만으로는 해결되지 않아 새 학습 데이터가 필요합니다.

기록한 동적 구간을 약 2Hz로 추려 필터 없이 투영한 점검에서는 조건별로 24–53%만 표시 기준을 통과했습니다. 이는 위치 정확도가 아니라 모델의 표시 허용 비율이며, 앱의 필터까지 적용한 실시간 결과와 다릅니다. 현재 네 모서리 보간으로는 움직임 전체를 안정적으로 설명하지 못합니다. 점이 자주 보류되는 것은 이 한계를 드러내는 동작입니다. 실제 내부 정지 위치를 추가로 측정해 모델을 보강할 필요가 있습니다.

첫 실제 분석: `reports/first-real/index.html`, 원본 세션: `data/completed-20261015`. 원본 다섯 센서의 행 수는 manifest의 개수와 일치하며 SHA-256은 `source_inventory.json`에 있습니다. 접촉·공중 각각 처음 2회차를 기준으로 세 번째 회차의 모서리 4곳을 확인했습니다. 배포 모델에는 각 모드의 세 회차 모두를 사용하므로 이 배포 모델 자체의 독립 성능 검증 결과로 혼동하지 마세요.

## 설치

1. 데이터 전송을 지원하는 **USB‑C 케이블로 iPad와 Mac을 연결**합니다. iPad 잠금을 풀고 ‘이 컴퓨터를 신뢰’를 승인합니다. 충전 전용 케이블은 사용할 수 없습니다.
2. `MagAir.xcodeproj`를 Xcode로 엽니다. 현재 Mac에 Xcode 26.2가 설치되어 있습니다. 앱의 최소 지원 버전은 iPadOS 17입니다.
3. Xcode → Settings → Accounts에서 본인의 Apple Account를 추가합니다. 개인 기기에서 시험하는 데 유료 개발자 멤버십은 필수가 아닙니다.
4. 왼쪽 파란 **MagAir 프로젝트 → TARGETS의 MagAir → Signing & Capabilities**를 선택합니다. `Automatically manage signing`을 켜고 `Team`에서 본인 계정의 Personal Team을 선택합니다.
5. Bundle Identifier가 이미 사용 중이라고 나오면 `com.본인이름.magair`처럼 본인 고유 값으로 바꿉니다.
6. iPad 설정 → 개인정보 보호 및 보안 → **개발자 모드**를 켜고 재시동 후 다시 확인합니다. 이 메뉴가 없으면 먼저 Xcode에서 기기 연결·페어링을 시작하세요.
7. Xcode 위쪽 실행 대상을 실제 iPad로 선택하고 **▶ 또는 ⌘R**을 누릅니다. 최초 기기 준비에는 시간이 걸릴 수 있습니다. iPad에서 개발자를 신뢰하라는 안내가 나오면 설정 → 일반 → VPN 및 기기 관리에서 본인 개발자 항목을 신뢰합니다.
8. 실행 후 동작 센서 권한을 요청하면 허용합니다. `자력계 연결됨`과 실측 Hz, Bx·By·Bz 변화를 확인합니다.

Apple 계정 로그인, 기기 신뢰와 개발자 모드 확인은 본인 기기에서 수행해야 합니다. 소스가 빌드되는 것과 개발자 서명을 거쳐 실제 기기에 설치되는 것은 별도 단계입니다. iPadOS가 설치된 Xcode의 기기 지원 범위보다 최신이면 Xcode의 안내에 따라 호환 버전이 필요할 수 있습니다.

무료 Personal Team의 프로비저닝은 보통 7일 후 만료되어 다시 빌드·설치해야 합니다. 기존 앱을 삭제하면 수집 데이터도 사라질 수 있으니 먼저 ZIP을 내보내세요.

첫 설치 후 앱 자체는 Mac 없이 동작합니다. 케이블을 뺄 경우 **배경 자기장 수집 전에** 빼고, 세션 중에는 충전 상태·케이블 위치·스탠드·케이스·주변 금속 배치를 바꾸지 마세요. 앱 실행을 Xcode에서 중지했으면 iPad 홈 화면에서 MagAir를 다시 여세요.

Apple 공식 안내: [기기에서 앱 실행](https://help.apple.com/xcode/mac/current/en.lproj/dev5a825a1ca.html), [개발자 모드](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device), [Personal Team 제한](https://developer.apple.com/help/account/basics/about-your-developer-account).

## 이전 실험 기록 · 네 모서리 수집

지금은 자를 사거나 5×5 격자를 그릴 필요가 없습니다. 앱 왼쪽의 **‘처음에는 이것만’** 목록을 사용하세요. 이미 그려둔 사각형의 모서리만 있으면 됩니다.

1. **시작 배경 자기장**: 펜슬을 충분히 멀리 둔 뒤 측정 시작 → 준비 3초 + 측정 10초.
2. **네 모서리에서 멈추기**: 왼쪽 위 → 오른쪽 위 → 오른쪽 아래 → 왼쪽 아래 순서입니다. 위쪽은 iPad 쪽, 아래쪽은 사용자 쪽입니다.
3. 화면에 표시된 모서리에 펜 끝을 대고 **‘위치 준비 완료 · 측정’**을 누릅니다. 처음 3초는 자세를 잡고 손을 안정시키는 시간입니다. 다음 3초는 펜을 움직이지 않고 재는 시간입니다.
4. 저장되면 다음 모서리로 이동해서 버튼을 누릅니다. 네 곳을 세 바퀴 측정하므로 **총 12번**입니다. 모서리 사이로 움직이는 시간에는 정지점 정답을 붙이지 않습니다.
5. 이어서 시계·반시계 테두리와 두 대각선을 화면의 안내점에 맞춰 따라갑니다. 선을 추가로 긋거나 중앙을 표시할 필요는 없습니다.
6. **종료 배경 자기장** → 세션 종료 → 저장 기록 → ZIP 공유.

이 실험은 네 모서리 신호의 구별 가능성과 반복성을 검사합니다. 분석 도구는 1·2회차로 모서리별 기준을 만들고 3회차의 네 위치를 구별해 봅니다. **영역 내부의 정확한 좌표나 글씨 복원 성능을 검증한 것은 아닙니다.** 그 검증은 이후 내부 표식을 추가한 정밀 실험에서 진행합니다.

## 추가: 접촉과 약 1cm 공중 비교

앱 왼쪽 **‘추가: 접촉 · 약 1cm 공중 비교’**에서 선택합니다. 높이는 **책상 표면에서 펜 끝까지**입니다. 첫 비교는 약 1cm로 정했으며, 자가 없으면 눈대중으로 매번 최대한 같은 높이를 유지하세요. 펜은 책상에 수직, 로고는 왼쪽을 유지합니다. 이 높이가 최적이라는 의미는 아니며 실제 데이터를 보고 다음 높이를 정합니다.

- **모서리 접촉 ↔ 공중**: 표시된 모서리에 댄 채 시작 → 준비 3초 → 접촉 정지 3초 → 2초 동안 수직으로 들어 올리기 → 약 1cm 공중 정지 3초 → 2초 동안 내리기 → 다시 접촉 정지 3초. 끝나면 다음 모서리로 옮겨 시작합니다. 네 모서리 × 3회, 총 12번이며 한 번에 준비 포함 16초입니다.
- **공중 테두리 · 시계 / 반시계**: 해당 방향의 접촉 테두리와 같은 경로를 약 1cm 띄워 따라갑니다. 각각 12초에 한 바퀴 × 5회입니다. 네 변이 모두 포함됩니다.

추가 비교를 마친 뒤 종료 배경 자기장을 기록하세요. 높이 전환 중 데이터는 보존하되 정지 상태 비교에서는 제외합니다. 분석은 각 모서리에서 들어 올리기 전·내린 후 접촉 값과 공중 값을 비교하며, 내부 좌표 학습에는 섞지 않습니다. `instructed_tip_height_mm`의 0/10은 **접촉/약 1cm를 안내했다는 기록**이며 실제 높이·접촉 감지 결과가 아닙니다. 손으로 맞추는 위치와 기울기 오차도 포함될 수 있습니다.

## 이후 정밀 좌표 매핑 · 5×5 / 4×4의 의미

이 항목들은 앱의 **‘나중에 · 정밀 / 추가 측정’** 안에 있습니다. 첫 실험에는 필요하지 않습니다. 5×5는 위치를 학습하기 위한 25개 점, 4×4는 학습하지 않은 위치도 맞히는지 확인하기 위한 16개 점입니다.

설정과 버튼을 포함한 앱 화면은 한국어입니다. 상세 실험 설계는 [실험 프로토콜](docs/PROTOCOL.md)을 참조하세요.

1. 이미 그려둔 직사각형을 그대로 사용합니다. 사용자 시점에서 먼 쪽 왼쪽을 `(0,0)`, 오른쪽을 `+x`, 사용자 쪽을 `+y`로 정합니다. 화면을 보고 책상 위치로 옮기는 좌표입니다. 센서의 기기 축과는 다릅니다.
2. 각 변을 4등분해 **5×5 교차점 25개**를 표시합니다. 자가 없으면 종이띠를 접어 4등분한 길이로 나눌 수 있습니다. 표식은 iPad와 영역을 이동시키지 않고 만들어 주세요.
3. ‘실험 조건’에서 사각형 비율, 케이스·충전 여부 등을 기록하고 **‘이 조건으로 준비 완료’**를 누릅니다. 기본 비율은 사용자가 확인한 **가로 1.5 : 세로 1**입니다. mm 치수는 모르면 비워 둡니다. 이후 **‘측정 시작’**을 누르면 세션이 자동으로 생성됩니다.
4. **시작 배경 자기장**: 펜슬을 멀리 치워 센서가 배경 수준으로 돌아온 상태에서 10초 기록합니다.
5. **5×5 좌표 학습**: 표시된 점으로 이동 → ‘위치 준비 완료 · 측정’ → 준비 3초 → 정지 3초. 총 25점×3회, 순서는 섞여 있습니다. 다음 위치는 자동으로 넘어가지만 측정 시작은 매번 직접 누릅니다. 터치할 때 iPad를 밀지 마세요.
6. **4×4 새 좌표 검증**: 앞서 표시한 16개 칸의 중심을 측정합니다. 16점×2회입니다.
7. **시계 테두리 / 반시계 테두리**: 왼쪽 위에서 시작해 화면의 안내점을 따릅니다. 12초에 한 바퀴, 총 5회. 한 변당 3초이므로 긴 변에서는 조금 더 빠르게 움직입니다.
8. **두 대각선**: 편도 6초, 왕복 12초, 총 5회씩입니다. 가로·세로 왕복도 같은 방식입니다.
9. 마지막으로 **종료 배경 자기장** 10초 → ‘세션 종료’ → ‘저장 기록’ → ‘이 세션 ZIP 만들기’ → ‘준비된 ZIP 공유’를 누릅니다.
10. AirDrop으로 Mac에 보내거나 파일 앱에 저장하고, 생성된 **ZIP을 그대로 이 대화에 첨부**하면 됩니다. 처음에는 배경+학습+검증만 보내도 분석을 시작할 수 있습니다.

정밀 세트는 위치를 잡는 시간에 따라 약 20~30분입니다. 피곤하면 한 동작이 끝난 후 쉬어도 됩니다. 다만 세션 중 배치가 바뀌면 새 세션을 만드세요. iPad IMU는 기기 흔들림을 보는 보조 데이터이며 펜의 기울어짐·회전 여부를 직접 알 수는 없습니다.

실수하면 ‘중단 · 다시 측정’ 또는 ‘직전 재측정’을 사용합니다. 앱을 배경으로 보내거나 화면을 잠그면 세션이 중단 저장됩니다. 강제 종료 시에도 2초마다 저장한 CSV와 상태가 남으며, 완료 처리되지 않은 trial은 분석에서 제외됩니다. 화면이 켜진 채 수집하도록 자동 잠금을 막습니다.

## 저장 내용

- `manifest.json`: 기기/OS, 고정 조건, 좌표 정의, 시계 기준, 요청 Hz, 센서 가용성, 각 trial의 시작·종료·완료/중단/무효 상태, iPad 움직임 경고
- `magnetometer.csv`: iPad 원시 3축 자기장, µT
- `accelerometer.csv`: iPad 원시 가속도, g
- `gyroscope.csv`: iPad 원시 회전속도, rad/s
- `device_motion.csv`: iPad 중력, 사용자 가속도, 회전속도, quaternion
- `pencil_events.csv`: 앱 화면에 접촉하거나 지원 범위에서 호버 이벤트가 들어올 때의 화면 좌표·기울기·방위각·압력/호버 높이 보조 기록. 책상 위치 정답이나 원시 IMU가 아닙니다.
- `README.txt`: 파일 해석 시 주의할 점

센서별 실제 타임스탬프를 기록합니다. 같은 CSV 행 번호끼리 센서가 동기화되었다고 가정하면 안 됩니다. 요청 주파수는 50 Hz지만 실제 주파수는 하드웨어/OS에 따라 달라집니다. 원시 자기장은 배경 제거·평활화 없이 보존합니다.

화면 밖 Apple Pencil 원시 IMU는 공개 API로 제공되지 않습니다. 이번 구현의 **IMU는 iPad 자체 센서**입니다. Pencil의 화면 접촉/hover 이벤트는 수신될 때만 별도 파일에 보존합니다. `altitude_rad`는 화면 평면 기준 기울기, `azimuth_rad`는 앱 window 좌표 기준 방위각입니다. 책상 기준 90°와 같지 않습니다. `hover_z_normalized`는 mm가 아닙니다. A2051은 축 회전각을 제공하지 않으므로 `roll_rad`는 빈칸입니다. 측정되지 않은 값을 0°로 기록하지 않습니다.

접촉은 `UITouch.timestamp`, 호버는 API가 개별 센서 시각을 노출하지 않아 콜백 수신 uptime을 기록합니다. `timestamp_basis`로 구분합니다. 이벤트가 없는 책상 구간에는 값을 채워 넣지 않습니다. 접촉의 보정 업데이트는 `estimation_update_index`, `estimated_properties`, `expecting_updates`로 식별합니다. 이 부가 데이터가 있다고 해서 책상 위 펜의 자세를 알 수 있는 것은 아닙니다. [Apple Core Motion](https://developer.apple.com/documentation/coremotion/cmmotionmanager), [자력계 간격과 실제 타임스탬프](https://developer.apple.com/documentation/coremotion/cmmotionmanager/magnetometerupdateinterval), [Pencil 호버 속성](https://developer.apple.com/documentation/uikit/uihovergesturerecognizer), [Pencil 상호작용 API](https://developer.apple.com/videos/play/wwdc2024/10214/).

네트워크 통신, 로그인, 서버 업로드, 외부 패키지가 없습니다. 저장 폴더는 파일 앱 → 나의 iPad → MagAir → MagAirSessions에서도 확인할 수 있습니다.

## Mac에서 1차 분석

Python 3.9 이상이며 외부 패키지가 필요 없습니다.

```sh
python3 scripts/analyze_session.py /path/to/MagAir-session.zip --out reports/first
open reports/first/report.html
```

결과는 `report.html`, `report.json`, 학습 가능할 경우 `model.json`입니다. kNN 기준 모델을 사용하며:

네 모서리만 수집한 세션은 모서리 구별 검사만 보고하며, 내부 좌표 모델을 만들지 않습니다. 아래 좌표 오차 평가는 정밀 격자 데이터를 수집한 세션에 적용합니다.

높이 비교 세션은 `height_check`에 세 정지 구간별 3축 중앙값·잡음, 공중과 접촉 간 자기장 거리, 다시 접촉했을 때의 변화량을 따로 보고합니다. 들기/내리기와 정지 구간 양끝은 제외하고, 세 구간 모두 충분히 수신된 완료 측정만 비교합니다. 높이 추정 정확도나 접촉 감지 정확도를 계산한 것은 아닙니다.

- 학습점 1·2회차로 학습 → **3회차 전체 trial**을 평가합니다. 같은 정지 구간의 이웃 샘플을 무작위로 나누지 않습니다.
- 학습점 전체로 학습 → **별도로 측정한 칸 중심**을 평가합니다.
- 한 정지 구간의 앞 0.4초/뒤 0.2초를 제외하고 3축 중앙값으로 분석합니다. 이 결과는 실시간 개별 샘플 추적 성능과 다릅니다.
- 중단·무효·미완료·수신 부족·큰 센서 공백 구간을 제외합니다.
- 치수가 없으면 가로·세로 비율 단위의 오차만 보고합니다. 임의로 mm 정확도를 만들지 않습니다.
- 이동 경로의 안내 좌표는 `guide_only`입니다. 이를 정답으로 학습하거나 경로 오차를 평가하지 않습니다.

격자 분석의 `model.json`은 오프라인 기준 모델입니다. 앱의 `live_model.json`은 별도의 네 모서리 보간 파일이며 내부 위치 성능을 검증한 모델이 아닙니다. `python3 scripts/build_live_pilot.py data/completed-20261015`로 해당 실제 세션에서 재생성합니다.

## 개발 및 검증

SwiftUI + Core Motion, iPadOS 17+, 외부 의존성 없음. 기존 Xcode 프로젝트를 바로 열면 됩니다. Swift 파일을 추가한 뒤 프로젝트 재생성이 필요하면 `python3 scripts/make_project.py`를 실행할 수 있습니다. 기존 Team/Bundle Identifier는 유지하지만 그 밖의 프로젝트 수동 변경은 덮어쓸 수 있습니다.

```sh
xcodebuild -project MagAir.xcodeproj -scheme MagAir \
  -destination 'generic/platform=iOS' -derivedDataPath build/DerivedData \
  CODE_SIGNING_ALLOWED=NO build
mkdir -p build/tests
swiftc -module-cache-path build/SwiftModuleCache \
  MagAir/Core/Experiment.swift MagAir/Core/EdgeExperiment.swift MagAir/Core/DenseGridProtocol.swift \
  MagAir/Core/GridLiveModel.swift MagAir/Core/SessionStore.swift \
  tests/CoreTests.swift -o build/tests/CoreTests
build/tests/CoreTests "$PWD/build/tests"
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

테스트의 합성 데이터는 파일 형식과 분석 로직을 검증하기 위한 것입니다. 실제 센서 정확도를 입증하지 않습니다. 실기기에서 권한·자력계 수신·10초 배경 측정·ZIP 공유를 한 번 확인한 후 본 실험을 진행하세요.
