# 2초 정지 · 행 안 자동 진행

앱 1.16.0부터 273점의 **이동·준비 2초 + 정지 수집 2초**를 사용합니다. 배경은 종전대로 준비 3초 + 수집 10초입니다. 현재 모델과 기존 1회차 원본은 바꾸지 않습니다.

1. 같은 배치·자세를 유지하고 **14/39 · 2회차 · 13행**부터 이어갑니다. 첫 회차의 13행 완료 이력은 유지됩니다.
2. 펜과 이동 홀더를 멀리 두고 **시작 배경** 버튼을 누릅니다.
3. 해당 행의 첫 점에 놓고 **연속 시작**을 누릅니다. 자동 진행을 켜 두면 이후 20개 점은 버튼 없이 이동·준비 2초 → 정지 2초를 반복합니다.
4. 짧은 음은 준비, 높은 음은 정지 측정 시작, 두 번 음은 다음 점으로 이동하라는 뜻입니다. 화면에 다음 행·열과 목표점이 표시됩니다. 출력 음량을 확인하세요.
5. 이동이 늦거나 잘못 놓았으면 **일시정지 · 이 점 다시**를 누릅니다. 현재 시도는 제외하고 같은 점에서 다시 시작합니다. 정지한 동안 `직전 다시`로 앞선 점도 재측정할 수 있습니다. 앱은 실제 펜이 표식에 도착했는지 감지하지 못합니다.
6. 마지막 점 다음에는 자동으로 멈춥니다. 펜을 멀리 옮긴 뒤 **종료 배경**을 직접 시작합니다. 저장을 확인하고 다음 행으로 넘어갑니다. 다른 행은 자동 시작하지 않습니다.

iPad 움직임·자력계 수신 중단·사용자 취소가 발생하면 자동 진행을 멈춥니다. 잠금/백그라운드로 중단된 행은 기존처럼 새 시작 배경부터 다시 수집합니다. 자동 진행을 끄면 2초 정지 설정으로 각 점을 수동 시작할 수도 있습니다.

센서 지연 수신을 기다리는 0.4초를 포함하면 한 행은 약 **119.2초**, 13행은 약 **25.8분**입니다. 처음 위치 맞춤·배경 이동·휴식·재측정은 별도입니다. 남은 두 회차의 순수 흐름은 약 52분입니다.

## 3초를 모두 써야 하는가

기존 학습은 단순 평균이 아니라 각 3축의 **중앙값**을 사용하고, 정지 구간 앞 0.4초와 뒤 0.2초를 제외합니다. 따라서 기존 3초 수집에서 실제 대표값에 쓰는 구간은 약 2.4초, 새 2초 수집에서는 약 1.4초입니다. 짧아진 구간에도 최소 50샘플·1.25초 범위·최대 센서 공백 0.15초·산포 3µT 미만을 요구합니다. 기존 3초 자료의 기준은 그대로입니다.

첫 회차 273개 정지 구간을 잘라 비교한 진단입니다. 독립 정확도 결과가 아닙니다.

| 수집 구간 | 남은 샘플 최솟값 | 3초 대표 자기장과 차이 중앙값 | 차이 95백분위 | 동일 지도에서 좌표 변화 95백분위 | 최대 좌표 변화 |
|---|---:|---:|---:|---:|---:|
| 앞 2초 | 69 | 0.095µT | 0.195µT | 0.278mm | 2.667mm |
| 앞 1.5초 | 44 | 0.141µT | 0.284µT | 0.374mm | 1.362mm |

두 경우 모두 좌표 변화 중앙값은 검색 격자상 0mm입니다. 최대 변화는 역매핑의 모호성 때문에 단조롭게 줄지 않습니다. **품질이 완전히 같다는 보장은 아니며**, 보유 자료에서 더 많은 샘플과 작은 자기장 변화를 보인 2초를 우선 사용합니다. 1.5초는 이번 앱에 적용하지 않았습니다.

이 진단은 이미 준비 3초 후 멈춰 있던 자료를 잘랐습니다. 준비 2초나 자동 이동의 품질까지 검증하지 못합니다. 새 자료의 정지 구간 산포와 회차 간 사전 평가로 확인합니다. 재현 명령은 `python3 scripts/check_hold_duration.py`이며 상세 결과는 로컬 `reports/duration-check-20261124.json`에 있습니다.

## 기록 구분

`timingRevision=printed_2s_prepare_2s_hold_v2`와 점별 `acquisitionSeconds`, `preparationSeconds`, 실제 `settleSeconds`를 저장합니다. 각 시도의 `startTrigger`는 수동/자동 시작을 구분합니다. 새 목표 라벨은 `scheduled_static_target_unverified`로, 사람이 매 점 버튼을 눌렀던 과거 `manual_static_target`과 구분합니다. 기존 파일을 다시 쓰지 않습니다.

2회차를 마치면 분석을 요청하고 3회차는 잠시 기다립니다. [회차 간 평가 기록](../evaluation/README.md)에 먼저 결과를 남기고, 1+2회차 모델 적용 후 3회차를 진행합니다.

## 구현 확인

Swift의 구간 경계·기존 13행 복원·자동 진행/중단 검사와 Python 검사 41개를 통과했습니다. 실제 1회차 원본으로 고정 모델이 동일하게 재생성되는지 확인했고, 시뮬레이터 화면 및 iPad 빌드·설치·실행을 확인했습니다. 업데이트 전후 iPad의 196개 원본 파일 크기·수정 시각은 같습니다. 실제 새 자동 이동의 측정 품질은 2회차 자료로 확인합니다.
